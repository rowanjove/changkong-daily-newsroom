# 08 · 编辑部桌面（v2）

目标：成品像编辑部定稿，不是每篇套同一分析模板。优先减法、分层、审校、去模板化。

定稿量级参考：最值得知道的约 20–30 条 + 主线 0–4 条。敢于删 / 降 / 折。

## 1. 事件簇（克制）

同公司/同访问/同冲突/同事故/同政策链/同技术披露 → 一条主新闻 + 2–5 子事件 + 可选时间线。

- 仅上述同类链才簇；松散主题（「都是 AI」）不簇。  
- 整簇仅一个 why + 一个 next（写在 lead）；satellite 不套完整分析。  
- 字段：`event_cluster_id`、`cluster_role`、`timeline`、`satellites`。

## 2. 版面层级

- **今日提要**：`summary` / forecast 导读，不是未来清单。  
- **头条瘦身**：标题 + 短摘要 + 2–3 关键事实 + 跳转 `#story-<id>`；禁止复制完整正文。  
- **主栏 4–6 + 更多新闻**：中/际/科技 ≈5、财经 ≈4；勿塞弱条；折叠仍计入版面上限。  
- **display_tier / attention_tier**：无强制数量。  
- **降级逻辑**：同事件次级、弱影响、前日轻微补充、小众专业、单源非重大、无实质变化、版面竞争。

## 3. 接下来关注（upcoming）

三桶：今晚 / 未来24小时 / 未来3天。总量 3–5；弱则整模块隐藏；禁止「本日暂无」占位。

## 4. 今日主线（Narrative Layer）

- 0–4 条；须因果链 / 方向变化 / 阶段演变 / 跨栏主线。  
- **唯一规则：** 每条 `supporting_story_ids >= 2 AND supporting_claim_ids >= 1`；不足 → **整条隐藏**。  
- 禁止换句复读标题；禁止 filler。  
- 不得引用未核验 claim；无证据因果词须降级。  
- 对照：`claims.validate_narrative_trends`、`sanitize_public._filter_narrative_trends`。

## 5. 跨栏关联（轻量）

`related_event` + `related_event_label` → 「关联事件：…」。不建专题页。

## 6. 证据状态（公开）

已确认 / 基本确认 / 单源 / 来源冲突 / 待确认 + 可选 `evidence_note`。  
勿把单源/冲突抬成已确认。禁旧「高可信」三词。

## 7. why / next_watch — 严格可选

**默认省略。** 宁可只有关键事实 + 来源。

- why：仅正文推不出的具体增量；泛泛/复读/意义拔高 → 省略。  
- 事实锁：仅 `verified|qualified`；需新事实打回给事中。  
- next：仅可验证外部节点（已定日期会议/财报/裁决/待公布数据等）；「继续观察」类 → 省略。  
- 编辑部核查任务不得进公开 next。

## 8. 严禁内部痕迹进 HTML

核验指令、与昨日对齐、补预印本、TODO 等只进 `editor_notes`。  
扫描：`title`/`summary`/`why`/`next`/`key_facts`/trends/upcoming。

## 9. 读者视角检查清单（定稿必过）

1. 10 秒抓住「发生了什么」？  
2. why 能删则删。  
3. next 是否可验证节点？否则删。  
4. 标题像新闻而非数据表？  
5. 主栏有无弱条该折「更多」？  
6. 趋势是否跨篇主线？  
7. 公开文案有无内部指令？  
8. 证据标签是否诚实？  
9. 同事件是否过度平行占栏？  
10. 全站最重要新闻是否被埋？  

不通过 → 重写 / 降 / 并 / 删。
